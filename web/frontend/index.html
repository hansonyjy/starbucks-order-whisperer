How it works

      
I designed and built this three-stage pipeline myself. Here's what happens between your query and the ranked list.


      

        
1

        
Extract — natural language → structured constraints

        
Your query goes to Claude (Haiku 4.5) with a strict JSON schema attached, so the reply is always valid JSON — no regex, no markdown-stripping, no parse failures. It maps phrases like "no dairy", "pick me up" or "under $5" to typed fields: dairy_free: true, caffeine_level: "high", max_price: 5. Ambient weather ("it's hot out") does not set temperature: iced. A bare "iced coffee" maps to a coffee umbrella category spanning brewed, cold brew and espresso, and "black coffee" sets no_milk: true — stronger than dairy_free, since it excludes plant milks too.

      


      

        
2

        
Filter — hard rules knock out non-qualifying drinks

        
Pure deterministic logic. Category, temperature, calorie cap, sugar cap, price cap, dairy-free, vegan, black/no-milk and caffeine level all become strict filters. Caffeine "levels" map to mg ranges derived from the training data, including a deliberate medium/high overlap at 150–200mg because that's what the ground-truth labels say. If the filters are too strict and nothing survives, constraints are relaxed progressively (price, then sugar, then calories) until something does.

      


      

        
3

        
Rank — constraint margin first, semantics as tiebreaker

        
Each survivor gets a constraint margin score: how comfortably it sits inside your limits. Under a 250-cal cap, a 0-cal drink beats a 200-cal one. Caffeine-seeking queries rank by most caffeine, "keep it mild" by least. Semantic similarity breaks ties the constraints can't separate, but it's bounded by ε = 0.001 so it can never flip drinks whose constraint scores genuinely differ. The competition build uses local all-MiniLM-L6-v2 embeddings; this live demo uses lightweight TF-IDF so it fits free-tier hosting.

A solo rebuild of a 1st-place solution

          
My team placed 1st of 19 at the UCLA × Starbucks Data Challenge. Afterward I rebuilt the system from scratch on my own: margin-first ranking instead of similarity-first, structured JSON output instead of fragile prompt-and-parse, and a local embedding model instead of a paid, rate-limited API.
